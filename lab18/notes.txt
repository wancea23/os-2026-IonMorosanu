Observe
thread_switch saves and loads the callee-saved registers, exactly the fields of struct context:
ra, sp and s0..s11 (14 registers, 112 bytes). It stores them from the CPU into the context of the
old thread (a0) and loads them from the context of the new thread (a1). The other registers
(a0..a7, t0..t6) are not kept, because thread_switch is called like a normal C function: the
caller already saves on its stack what it needs after the call.
ra makes the execution go on in the other thread because ret is a jump to the address in ra.
After the new ra is loaded, ret goes where that thread stopped (right after its call to
thread_switch inside thread_schedule), or, for a thread that never ran, to its function, because
thread_create wrote the function address in ra. sp is loaded together with ra, so the code runs
on the stack of the new thread.
