Answers

1. The mask 32 is 2^5, so only bit 5 is on, and 5 is SYS_read. The kernel prints a call only when
   (p->trace_mask >> num) & 1 is 1. For open (15) and close (21) that bit is 0, so they run but are not printed.
   With all the bits on (2147483647) grep shows them too: open -> 3 and close -> 0, plus trace and exec.

2. np->trace_mask = p->trace_mask; in kfork() (kernel/proc.c). Without it a child would not get the mask of its
   parent (its field keeps whatever its slot of the process table held, 0 for a slot never used), so the children
   would print nothing. With it the children and the children of the children inherit the mask of trace.
   In my run not three but thirteen processes printed lines (pids 7 to 19). 7 is usertests itself, which forks
   8 to run the test; 8 forks 9 and then sleeps for two seconds; 9 forks in a loop, and every child it creates
   runs the same loop, so the children fork as well. Which of them get to fork before the table is full depends
   on the scheduler: on one CPU many of them got a turn, in the handout's run three did. Pid 19 got the last free
   slot (68) and then -1, because all 64 slots of the process table (NPROC) were in use. After that failure the
   test creates the file stopforking, every looping process sees it and exits, and the test passes.

3. echo calls write twice: once for the word "hi" (2 bytes) and once for the "\n" at the end (1 byte), as the two
   lines show. The kernel prints the trace line as soon as the first write returns, before echo makes the second
   one. Both go to the same console, so the line lands between "hi" and the newline.

4. open is 15 and close is 21, so the mask is 2^15 + 2^21 = 32768 + 2097152 = 2129920. trace 2129920 grep hello README
   printed only open -> 3 and close -> 0.
